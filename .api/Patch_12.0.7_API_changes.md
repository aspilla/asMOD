### 2026-04-30
[Midnight 12.0.7 and Classic PTR Changes I](https://discord.com/channels/327414731654692866/1499463604121112707)

> Hello again from Blizzard! With 12.0.7 PTR starting up soon, here is a list of the addon API changes you can expect to see.
>
> DISCLAIMER: These notes are for addon authors and as such are focused specifically on addon-facing API and security changes only. Changes planned for other parts of the game (UI or otherwise) are not included here.

<details open>
<summary>Coming in 12.0.7 PTR 1</summary>

**Tooltip Money Display**
* Added a new `GameTooltip_AddMoneyLine` API, which uses embedded atlases to render money (via a new MoneyFormatter utility) rather than MoneyFrame.
  * Addons are advised to use the new API to avoid issues with secret values in tooltips.
  * All usages of `SetTooltipMoney` in our code have been removed.

**Unit Identity**
* APIs that restrict certain unit token types (such as `UnitGUID`, `UnitAura`, and health/power APIs when called with PvP-restricted tokens) will no longer raise Lua errors when fed an unsupported token. They will instead return nil or an appropriate default value.

**Encounter Events**
* `ENCOUNTER_END` now includes an additional payload: a list of EncounterUnitStatus tables for all boss units that were engaged during the encounter.
  * Each entry contains the unit's `creatureID`, `creatureName`, and `remainingHealthPercent` (as non-secrets) at the time they were killed/disengaged (or, when the encounter ended).
* `C_EncounterEvents` now allows configuration of different colors for text warnings and timeline events.
  * Additionally, a custom color can be defined for when a timeline event reaches the 5 seconds remaining mark, signaled via `ENCOUNTER_TIMELINE_EVENT_COLOR_CHANGED`.
* `C_EncounterEvents` now accepts alpha values for its color APIs.

**File Asset APIs**
* Added a new C_UIFileAsset namespace with the following APIs to help addons validate font and texture paths before using them:
  * `C_UIFileAsset.GetFileID(asset)` - returns the numeric file ID for a given path or file ID, or nil if the asset is not known to the client.
  * `C_UIFileAsset.IsKnownFile(asset)` - returns true if the asset is present in the shipped client data or is a known local loose file.
  * `C_UIFileAsset.IsLooseFile(asset)` - returns true if the asset is a locally known loose (non-shipped) file.

**Profiling APIs**
* The following profiling APIs have been made available to addons again: `GetEventCPUUsage`, `GetFunctionCPUUsage`, and `GetScriptCPUUsage`.

**Gamepad / SimulateMouse**
* SimulateMouse APIs (eg. `SimulateMouseDown`, `SimulateMouseClick`) no longer carry taint when used.
  * In order to allow them to run taint-free, these APIs have been restricted to only function when all current mouse foci are not forbidden, locked down, script inaccessible, or protected frames (while in combat).
  * They are still restricted to only being used via a gamepad action.

**Debug APIs**
* `debugstack` and `debuglocals` will now return secret values if the current function — or any caller up the stack — has accessed a secret value.

**Misc**
* Fixed various issues with secrets causing issues when present in regions displayed in scrollboxes.
* `C_ScenarioInfo.GetUnitCriteriaProgressValues` now returns its second value (a percentage) in the range [0, 1] rather than [0, 100].
* The default script error reporter dialog will no longer display a blank frame if there are non-printable characters such as null bytes in the text.
* Chat events for currency, honor, loot, money, reputation, and XP gains are no longer secret.
* Support has been added for per-directive conditionals in addon toc files (e.g. `## Dep: Addon_X [AllowLoadGameType classic]`).
* `SetFont` has more informative error messaging when supplied invalid font flag names.
</details>

<details open>
<summary>Coming in upcoming Classic PTR builds</summary>

* Most secret-related fields have been removed from the autogenerated Lua API documentation in Classic builds.
  * Fields such as `SecretArguments`, `ConditionalSecret`, `SecretPayloads`, and secret predicate documentation will no longer appear in the Classic API docs, since these concepts don't apply there.
* The `RemoveRaidTargets` API has been added to Classic.
* Various APIs for obtaining missing health and powers that operate on curves (and `UnitHealPredictionCalculator`) have been added to Classic.
* Minimap pings are no longer restricted in Classic.
* Raid target marker throttles are significantly relaxed in Classic.
* Macro-initiated chat and chat channel commands are no longer restricted in Classic.
* APIs that take limited subsets of unit tokens from tainted code are no longer restricted in Classic (this doesn't apply to `UnitTokenNameplate`).
</details>

### 2026-05-28
[Midnight 12.0.7 PTR Changes II](https://discord.com/channels/327414731654692866/1509594073680449650)

> Hello again from Blizzard! Today's 12.0.7 PTR build is our first 12.0.7 RC (there may be more), so here is a list of the addon API changes in this build, along with a review of some of the changes that went into recent 12.0.7 PTR builds since our last update. And then finally a short note with some timeline info about the upcoming Aura refactor.
>
> DISCLAIMER: These notes are for addon authors and as such are focused specifically on addon-facing API and security changes only. Changes planned for other parts of the game (UI or otherwise) are not included here.

<details open>
<summary>New in 12.0.7 RC 1</summary>

* Added a new `"set-unmarked"` option for the `raidtarget` secure action that will set a raid marker on the player's target if they don't currently have a marker on them.
  * The `/tm` command now supports this same behavior by using `~` preceding the marker index (e.g. `/tm ~4`).
* The following C_MythicPlus APIs now return CalendarTime structs instead of MythicPlusDate structs: `GetRunHistory`, `GetWeeklyBestForMap`, and `GetSeasonBestForMap`.
* The `GROUP_FORMED` event now gets correctly sent when the player joins a follower dungeon or delve on their own.
* The `isFromPlayerOrPlayerPet` bool in AuraData structs is now set to true if the aura came from a player-controlled vehicle.
* Addons are now allowed to call `C_UnitAuras.AddPrivateAuraAppliedSound` during an active M+ as long as the player isn't in combat.
* Fixed a bug that caused secret value errors in the `SetFrameStrata` API (often in chat-related code).
</details>

<details open>
<summary>Changes in other recent 12.0.7 PTR builds</summary>

* The identity of units with the `"npc"` unit token are no longer secret when the player is in an active item interaction with them.
* The `BNInviteFriend` API has been migrated to `C_BattleNet.InviteFriend` (and an occasions secrets-related Lua error was fixed as a result).
* Added a new `DurationTextBinding` script object type. This allows addons to bind a duration value directly to a font string, causing the string to update automatically based on the duration.

Example usage:
```lua
local duration = C_DurationUtil.CreateDuration();
duration:SetTimeSpan(GetTime() - 10, GetTime() + 20);
local secondsFormatter = C_StringUtil.CreateSecondsFormatter();
secondsFormatter:SetDefaultAbbreviation(Enum.SecondsFormatterAbbreviation.OneLetter);
secondsFormatter:SetStripIntervalWhitespace(Enum.SecondsFormatterIntervalWhitespace.Strip);
secondsFormatter:SetMillisecondsThreshold(5);

local binding = C_DurationUtil.CreateDurationTextBinding();
binding:SetFontString(PlayerName);
binding:SetDuration(duration);
binding:SetFormatter(secondsFormatter);
binding:SetExpiredText("Done!");
binding:SetZeroDurationText("");
binding:SetEnabled(true);
```
</details>

<details open>
<summary>Timeline for the Aura Refactor</summary>
As previously mentioned in past posts, we are working on a refactor of how we expose auras to addons. The high level goal of this refactor is to make auras much more secure while still allowing addons to create their own filtered aura displays and customize the way they are displayed. We are not quite ready to announce the technical details but are ready to tell you that we are currently targeting the 12.1.0 patch for these changes (subject to change as needed of course). We will be giving a full technical breakdown of the changes once they are solidified and reaching out to gather thoughts and feedback from several of you individually well before then, so stay tuned!
</details>
